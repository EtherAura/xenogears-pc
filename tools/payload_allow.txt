# tools/payloadcheck.py: port code (or, with a reason, game C) whose bytes match
# retail module data.
#
#   source[:symbol]  byte budget  # reason
#
# Patterns are fnmatch on "source:symbol" or on the source alone (bytes whose
# symbol is unknown, as merged strings or a PE file's local data, match an
# entry by its source). A source's bytes must stay within the sum of its
# entries' budgets. Anything else from port/ fails the check. None of this
# is game data: it is SDK data the port's own libraries reimplement, or
# coincidence (format strings, hex digits, runs of small consecutive numbers
# that a game table also holds).
#
# Optional "pe" prefix: Windows-only, exact source:symbol pattern and its
# own budget (no unknown-symbol fallback or pooling across symbols). Library
# member/symbol origins are checked against the linked map and object bytes.
